# ParkPark — 루프 작업 인수인계 (2026-10-13)

사용자가 자리를 비운 동안 에이전트가 스스로 계획 → 구현 → 검증 → 다음 단계 기획을 반복하도록 만든 문서입니다.
이 파일 하나로 (1) 추가할 에셋 36개, (2) 만들 시스템 백로그, (3) 루프에 넣을 프롬프트, (4) 안전 규칙을 모두 확인할 수 있습니다.
에이전트는 매 반복마다 이 파일의 **상태 열**과 `AGENTS.md`를 갱신합니다.

## 0. 현재 상태 요약

- 구역 10개(물, 어린이, 모험, 겨울, 우주, 해적섬, 사탕, 정글, 사막, 구름), 놀이기구·가게 57개, OBJ 126개, 템플릿 87개. 모델은 모두 가져온 상태입니다.
- 수입은 놀이기구가 초당 지급(`Income.luau`), 직접 수입은 줍기·낚시·배달·오늘의 미션(`ActiveIncome`), 이벤트 8종, 꾸미기 상점(코인 전용), 일일 보너스, 함께 놀기 보너스.
- 구역 추가는 생성기(`tools/generate_parkpark_meshes.py`)와 구역 정의 스크립트 방식으로 반복해 왔고, 새 구역은 정의 1개 + OBJ 7개로 끝납니다.
- 미해결: 폰 터치 확인(사용자), 후원자 패스 ID(사용자), 구역 10개 이후 맵 길이(z -2768)의 폰 성능 확인(사용자), 새 구역들의 손님 앉은 높이 샘플링.

### 2.1 새 구역 사양 (해저/로봇 도시 공통 규칙)

- 위치: 직전 구역 경계에서 263 스터드 북쪽. 분기 줄 위치는 경계에서 18/133, 놀이기구 위치는 73/188/158 안쪽(구름 구역까지와 동일).
- 연결: `Requires`는 직전 구역의 마지막 가게, 첫 구역 개방비는 직전 구역 개방비의 약 1.08배, 단계 비용은 직전 구역의 약 1.04배씩 증가.
- 요금 등급: 스피너·점프·투어·가게 순으로 직전 구역의 마지막 등급보다 약 +5%씩.
- 줍기 물건 이름·색, 분위기 효과(`*Service.luau` 한 개), 장식 구성(구역 전용 2종 + 기존 재활용 3종).
- 구역 정의는 `scratchpad/zones2.py`와 같은 스펙 기반 스크립트 방식을 유지합니다(저장소 도구로 옮길 때는 `tools/`에 추가).

## 3. 루프 안전 규칙 (모든 프롬프트에 공통)

1. **외부 변경 금지**: 게시, 에셋 구매, 로벅스 결제, 개발자 상품/패스 생성, 외부 서비스 호출을 하지 않습니다. ID를 지어내지 않습니다.
2. **돈 관련**: 유료 게임플레이 이점 금지. 꾸미기·편의 외 과금은 만들지 않습니다.
3. **저장 데이터**: 테스트는 항상 `ServerStorage.DebugUseMemorySaves=true`(실제 DataStore 미사용). 끝나면 값을 지웁니다. 사용자 계정의 실제 저장을 지우지 않습니다.
4. **Rojo**: 서버가 켜져 있는 동안 `assets/models/roblox`를 `git checkout`/삭제하지 않습니다. 템플릿을 만든 뒤 기존 파일의 줄바꿈 변경은 `git show HEAD:<파일> > <파일>`로 제자리 복원하고, 새 템플릿만 커밋합니다.
5. **README.md**는 사용자 소유입니다(삭제 상태 그대로 둡니다).
6. **작은 단위**: 한 반복에 한 항목. 커밋 메시지는 자연스러운 한 문장(한국어) + 저장소 규칙의 공동 작성자 줄.
7. **확인하지 않은 것을 확인했다고 쓰지 않습니다**. Studio 연결이 안 되면 "확인 대기"로 기록하고 코드 작업만 합니다.
8. **사용자 시간 절약**: 가져와야 할 OBJ는 쌓아 두었다가 한 번에 목록으로 남깁니다. 가져오기를 기다리며 멈추지 않고 그레이박스로 계속 진행합니다.
9. **정지 조건**: 같은 오류로 3번 연속 실패, `verify.ps1`을 3번 연속 통과 못함, 저장 데이터 손상 징후, 사용자 파일 변경 필요, 예상 못 한 대규모 diff(500줄 이상 삭제) 중 하나면 멈추고 `docs/LOOP_LOG.md`에 상황을 적습니다.
10. **예산**: 한 세션에서 최대 12 반복. 반복마다 `docs/LOOP_LOG.md`에 3줄(한 일 / 검증 결과 / 다음 계획)을 남깁니다.

## 4. 사전 점검 (사용자가 자리를 뜨기 전, 2분)

1. Roblox Studio를 열고 `ParkPark` 장소를 로드, Rojo 플러그인 `localhost:34872` Connect.
2. Studio 설정에서 `Enable Studio as MCP server` 켜짐 확인.
3. 터미널에서 `"%USERPROFILE%\.aftman\bin\rojo.exe" serve default.project.json`이 켜져 있는지 확인(없으면 프롬프트 A의 0단계가 직접 켭니다).
4. 노트북 전원/절전 설정: 절전 끔(루프가 끊기지 않게).
5. (선택) 가져오기가 필요한 OBJ가 쌓이면 `docs/LOOP_LOG.md` 맨 아래 "가져오기 대기 목록"을 보고 한 번에 가져오세요.
