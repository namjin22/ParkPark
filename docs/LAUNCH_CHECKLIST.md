# ParkPark 출시 점검표 (2026-10-13 기준)

현재 상태: 코드로 할 수 있는 기능 백로그는 끝났고, 모델 27개까지 가져와 모든 구역이 템플릿으로 렌더됩니다.
아래는 "출시 전에 무엇이 비어 있는가"를 우선순위로 정리한 것입니다. 표시: **[나]** 제가 코드와 Studio 검증으로 할 수 있음,
**[사용자]** 사용자만 할 수 있음(폰, 계정, 게시, 결정), **[함께]** 둘 다 필요.

## P0. 출시 전에 반드시 정해야 하거나 확인할 것

1. **공원 소유 구조 결정 [사용자 결정 → 나]**
   - 지금은 서버에 먼저 들어온 사람(방장)의 공원 저장본으로 서버가 만들어지고, 다른 사람은 코인과 꾸미기만 저장됩니다.
   - 방장이 아닌 사람이 코인을 써서 놀이기구를 고쳐도 자기 저장에는 남지 않습니다(방장의 저장에만 남음).
   - 선택지: (a) 한 서버 = 한 방장의 공원, 다른 사람은 방문객이라고 화면에 분명히 표시, (b) 서버마다 공원을 모두 함께 소유하고
     기여를 모두 저장, (c) 사람마다 자기 공원(예약 서버)에 들어가고 친구를 초대. 이 결정이 저장·화면·마케팅 문구를 모두 바꿉니다.
2. **여러 명 접속 시험 [나 + 함께]**
   - 지금까지 한 명으로만 시험했습니다. Studio의 서버 + 클라이언트 2~4명 모드로: 방장 교체, 파티 보너스,
     모노레일 동시 탑승, 좌석 이중 점유, 저장 잠금(두 서버가 같은 프로필을 쓰려 할 때), 퇴장 후 재접속을 확인해야 합니다.
3. **실제 폰에서 확인 [사용자]**
   - 관리 패널, 도감·미션·꾸미기·이동 버튼, 알림 위치, 모노레일 탑승, 길게 누르기(프롬프트), 가로/세로 화면.
   - 저사양 안드로이드에서 프레임과 메모리. 끊기면 `StreamingTargetRadius`, `MaxGuestsCap`, 장식 개수 순으로 줄입니다.
4. **진행 속도를 사람이 한 번 플레이 [사용자]**
   - 처음 10분(튜토리얼 흐름), 첫 1시간, 구역 문을 여는 순간이 지루하거나 막히는지 확인하세요.
   - 모델상 전체 약 23시간이고, 실제는 업그레이드와 이벤트 때문에 더 짧을 것입니다. 숫자는 `tools/pacing_model.py`로 바로 조정합니다.
5. **보안 점검 [나]**
   - 원격 이벤트(`RideAction`, `Closet`, `Travel`)는 서버가 거리·상태·코인을 검증하지만, 출시 전에 익스플로잇식 호출(잘못된 인자,
     초고속 반복, 열리지 않은 구역으로 이동)을 일부러 보내 보는 시험이 없었습니다.
   - 디버그 훅(`DebugSaveSeed`, `DebugResetSave`, `DebugUseMemorySaves`)에 `RunService:IsStudio()` 보호가 없습니다.
     게시본에 ServerStorage 값이 남으면 저장을 건드릴 수 있으므로 Studio에서만 동작하도록 막아야 합니다.
6. **저장 안전성 [나 + 함께]**
   - 새 저장 필드(Stats, Book, Week, Achievements, Stamps, Landmark_*)를 실제 DataStore로 한 번 왕복 확인(지금은 메모리 모드로만 확인).
   - 저장 실패 시 플레이어에게 보이는 알림과 재시도, 스키마 버전 필드(`v1` 범위만 있고 프로필 안에 버전이 없음) 추가.
   - 출시 후 롤백 계획: 게시 전 DataStore 키 백업 방법 정리.
7. **게시와 계정 설정 [사용자]**
   - 별도 시험용 장소(베타)에 먼저 게시, 아이콘·썸네일·설명·장르·지원 기기, 연령 등급 설문, 최대 인원 수, 비공개 서버 설정.
   - 장소 이름이 `Place8` 같은 임시 이름이면 바꿉니다. 저는 게시하지 않습니다(사용자 요청이 있을 때만).

## P1. 강하게 권장

- **언어/현지화**: 지금 모든 문구가 한국어뿐입니다. 한국 시장만 노린다면 그대로 두고, 아니면 `LocalizationService`로 영어를 추가해야
  합니다(문구가 코드에 흩어져 있어 작업량이 큼 — 먼저 목표 시장을 정하세요).
- **분석 지표 [나]**: Roblox의 `AnalyticsService`로 퍼널(첫 수리, 공원 열기, 첫 구역 개방, 10분/30분/1시간 접속 유지)과 경제 이벤트를 남겨야
  출시 후 어디서 떠나는지 알 수 있습니다. 지금은 아무 지표도 없습니다.
- **소리 [함께]**: 배경 음악, 구역별 분위기 소리, 놀이기구 소리가 없습니다(내장 효과음 3개뿐). 소리 자산은 직접 구매·업로드·권한이
  필요하므로 ID는 사용자가 정해 주셔야 합니다.
- **임시 도형 모델 교체 [나가 OBJ 생성 → 사용자가 가져오기]**: 열기구 전망대, 광장 시설 3종(매표소·후원사 간판·VIP 라운지),
  모노레일, 발전기, 청소 카트, 청소부, 정거장 키오스크는 아직 단순 도형입니다. 첫인상에 가까운 광장 쪽부터 교체하는 것이 좋습니다.
- **장시간 안정성 [나]**: 1~2시간 이상 서버를 켜 둔 상태에서 손님 수, 메모리, 팝업, 장식 개수가 늘어나지 않는지 확인.
- **조작 방식**: 프롬프트가 키보드 E 중심입니다. 게임패드(콘솔)에서 길게 누르기와 패널 조작이 되는지 확인하거나 콘솔 지원을 끕니다.
- **친구와 함께하기**: 친구 초대 버튼(`SocialService`), 서버 안 순위표(총 수입, 도감 완성)를 넣으면 첫 접속 후 재방문과 공유가 늘어납니다.
- **결제 정책 [사용자]**: 후원자 게임 패스는 코드만 연결돼 있고 `PassId = 0`입니다. 만들 것인지, 꾸미기를 로벅스 상품으로 팔 것인지,
  "수입 2배" 같은 능력 판매는 하지 않는다는 방침을 유지할지 정해 주세요.
