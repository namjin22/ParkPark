# ParkPark 출시 점검표 (2026-10-13, 두 번째 판)

표시: **[나]** 제가 코드와 Studio 검증으로 한 일, **[사용자]** 사용자만 할 수 있는 일(폰, 계정, 게시, 결정),
**확인함**은 Studio Play에서 실제로 본 것, **확인 못 함**은 도구나 환경 때문에 보지 못한 것입니다.

## P0 — 출시 전에 반드시

| 항목 | 상태 | 내용 |
|---|---|---|
| 공원 소유 구조 | 구현함, 일부만 확인 | **(c) 사람마다 자기 공원.** `OwnerService`: 공개 서버(로비)에 들어온 사람은 자기 예약 서버로 이동(친구 초대면 친구의 예약 서버), 예약 서버에서는 첫 사람이 주인, 나머지는 방문자. 방문자는 해금·수리·업그레이드·구역 열기·시설·꾸미기·직원을 못 하고(서버가 검사), 수입은 `VisitorIncomeShare` 0.5배. 확인함: 방문자 모의에서 해금 거부와 수입 절반, 주인 모의에서 정상. **확인 못 함:** 실제 텔레포트(게시된 장소에서만 동작, Studio에서는 로그만 남김). 텔레포트가 실패하면 기존 방식(그 서버에서 모두 관리 가능)으로 계속 진행합니다. |
| 여러 명 접속 시험 | 일부만 | Studio MCP는 한 명 Play만 지원해 두 명 이상 접속은 못 했습니다. 방문자 모의(`DebugPersonalPark`/`DebugVisitor`), 주인 고정(방장 교체 없음), 코드 검토만 했습니다. 게시한 베타 장소에서 친구와 확인 필요 [사용자]. |
| 폰 확인 | [사용자] | 터치, 가로/세로, 저사양 기기 프레임. 새 버튼이 늘었습니다: 이동·꾸미기·미션·도감·친구 공원·음악. |
| 직접 플레이 | [사용자] | 처음 10분과 첫 1시간. 진행 속도는 `tools/pacing_model.py`로 바로 조정. |
| 보안 | 확인함 | 원격 이벤트 8개에 잘못된 값 232회와 초고속 반복 300회를 보내도 서버 오류 없음, 코인·상태 변화 없음, 시도 제한 동작. 디버그 값(`DebugSaveSeed` 등)은 Studio에서만 읽도록 막음. 관리 권한은 서버에서 거부. |
| 저장 안전 | 확인함 | 실제 DataStore를 읽어 새 필드(`Stats`, `Book`, `Stamps`, `Achievements`, `WeekCounts`)가 이미 실제 저장에 있고 `Version` 필드가 있음을 확인. 불러오기 실패·저장 중단·저장 지연을 플레이어에게 알림. 더 새 형식의 저장은 건드리지 않음. 롤백은 게시 전 DataStore 키 백업이 필요합니다 [사용자]. |
| 게시 설정 | [사용자] | 임시 장소 이름 변경, 아이콘·썸네일·설명, 연령 설문, 베타 장소 먼저 게시. **콘솔(게임패드)은 확인하지 못했으니 지원 기기에서 콘솔을 끄는 것을 권합니다.** |

## P1 — 구현한 것

| 항목 | 상태 | 내용 |
|---|---|---|
| 분석 지표 | 구현함, 게시 후 확인 | `AnalyticsHub`: 온보딩 퍼널(접속, 입구 청소, 개장, 세 번째 놀이기구, 첫 구역), 코인 경제 이벤트(1분 합산), 구역·수리 개수 사용자 이벤트. Studio에서는 꺼져 있어 대시보드에서 확인해야 합니다. |
| 소리 | 구현함, 들어 보지 못함 | `MusicController`: 무료 라이브러리 음악 3곡을 돌려 재생(볼륨 0.25)하고 군중 소리 루프(0.1), "음악" 버튼으로 끄기. ID는 `GameConfig.Audio`에서 바꿉니다. 곡이 마음에 안 들면 알려 주세요. |
| 영어 화면 | 구현함 | `LocalizeController` + `Strings`: 한국어가 아닌 언어의 플레이어에게 영어로 표시(약 450개 문구, 조합된 문구는 줄·구분 단위로도 번역). 확인함: 샘플 상태에서 한국어가 남지 않음. 번역이 없는 문구는 한국어로 남습니다. 한국어 사용자는 그대로입니다. |
| 순위판 | 구현함, 게시 후 확인 | `LeaderboardService`: 공원 가치(수리한 놀이기구 비용 + 연 구역 비용)를 5분마다 OrderedDataStore에 올리고 광장 게시판에 상위 10명 표시. Studio·메모리 저장 모드에서는 꺼짐. |
| 친구 | 구현함, 게시 후 확인 | "친구 공원" 패널: 친구 초대(Roblox 초대창, 초대받은 친구는 내 공원으로 이동), 접속 중인 친구 공원 방문, 내 공원으로 돌아가기. 방문은 서버가 친구 관계를 확인합니다. |
| 장시간 안정성 | 확인함 | 놀이기구 66개·모든 구역·직원 3단계로 18분: 서버 인스턴스 약 18,000개로 안정, 손님 36명, 프레임 60fps(Studio), 비·무지개 정상, 오류 없음. Studio 메모리가 18분에 약 70MB 늘었음(분당 약 4MB, 기록만). |
| 임시 도형 교체 | 일부 | OBJ 5개 생성(`ParkParkLandmarkTicket/Sponsor/Lounge`, `ParkParkBalloonPad`, `ParkParkBalloonBalloon`), 가져오면 템플릿 제작. 모노레일 열차·발전기·청소 카트는 도형으로 유지. |

## P1 — 하지 못했거나 사용자 몫

- **결제:** 후원자 패스는 `PassId = 0`(만들지 않음). 패스·상품은 사용자 계정의 Creator Dashboard에서만 만들 수 있습니다.
  코드는 꾸미기 전용 방침을 유지합니다(능력 판매 없음).
- **게임패드:** 프롬프트는 기본 게임패드 키가 있고 패널 버튼은 선택 가능하지만 실제 패드로 확인하지 못했습니다.
- **음악 취향·길이:** 들어 보지 못했습니다.

## 제안 순서

1. 가져오기 대기 OBJ 5개 가져오기, 폰 확인 [사용자]
2. 베타 장소에 게시해 친구 2~3명과 접속 시험: 텔레포트, 방문, 초대, 순위판, 분석 지표 [함께]
3. 직접 플레이로 진행 속도와 음악 확인 [사용자]
4. 패스·상품 결정, 아이콘·썸네일·설명, 연령 설문, 콘솔 끄기 [사용자]
5. 공개
