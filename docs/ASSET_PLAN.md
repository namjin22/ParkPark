# ParkPark — MVP asset plan

## 목표와 범위

이 목록은 [`GAME_DESIGN.md`](GAME_DESIGN.md)의 작은 공원, 회전목마·티컵·범퍼카, 스낵 판매대, 짧은 이벤트를 위한 아트 제작 계획이다. 첫 플레이 가능한 구간은 입구 정리 → 회전목마 수리 → 손님 탑승 → 티켓 획득으로 읽혀야 한다.

현재 맵의 기본 `Part`와 회색 상자는 기능 확인용 graybox다. 그것을 최종 에셋으로 포장하거나 색만 입혀 최종 디자인으로 간주하지 않는다. 아래의 자체 제작은 의도한 실루엣·표면 디자인을 갖춘 별도 모델/모듈형 세트 제작을 뜻하며, Roblox Studio 작업은 이 기획의 범위에 포함되지 않는다.

## MVP 에셋 목록 및 제작 방식

| 우선순위 / 에셋 | 필요한 구성·상태 | 권장 방식 | 이유와 검수 포인트 |
| --- | --- | --- | --- |
| P0 회전목마 — 대표 에셋 | 중앙축, 원형 차양, 고유 피니얼, 좌석, 수리 콘솔, 폐허/복구 시각 상태, 켜짐/꺼짐 전구 | **전체 자체 모델링 권장** | 게임의 시각적 상징이자 첫 복구 순간이다. 외부 모델을 그대로 쓰지 말고 실루엣, 비율, 좌석, 차양 장식까지 ParkPark 전용으로 설계한다. 수리 전후를 같은 배치에서 토글할 수 있게 파손·복구 표현을 분리한다. |
| P0 입구·간판 | 둥근 아치/기둥, ParkPark 워드마크와 장식, 바랜 글자 상태 | **자체 제작 권장** | 첫 화면 구도를 만드는 고유 요소다. 짧고 큰 글자, 먼 거리에서 읽히는 대비, 회전목마를 가리지 않는 개방감을 확인한다. 기존 유명 공원 입구를 참고해 복제하지 않는다. |
| P0 첫 구역 바닥·동선 | 입구 광장, 중앙 보행로, 가장자리 포장, 잔디 경계 | **간단한 모듈/타일을 자체 제작** | 플레이어 동선과 카메라 프레이밍을 직접 조정해야 한다. 반복 패턴이 눈에 띄지 않게 변형하고 잡초와 잔해가 통행/수리 지점을 가리지 않도록 한다. |
| P0 폐허/복구 조경 키트 | 잡초 다발, 덩굴, 작은 잔해, 페인트 벗겨짐 데칼 또는 표면 변형 | **소형 키트 자체 제작** | 폐허 상태를 일관되게 만들고 회전목마 주변을 정돈할 수 있다. 적은 수의 재사용 가능한 형태로 제작하고 복구 때 숨기거나 정리한다. 깨진 유리의 날카로운 파편 묘사는 피한다. |
| P1 티컵 라이드 | 중심 장식, 플랫폼, 회전 컵 여러 개, 폐허/복구 색 상태 | **Creator Store 후보를 선별해 다듬기 권장** | 회전목마 다음 시설이라 빠른 콘텐츠 제작이 중요하다. 우선 직접 디자인한 컵/중심 장식으로 실루엣을 바꾸고, 재질·비율·색을 팔레트에 맞춘다. 적합한 모델이 없거나 유명 시설을 연상시키면 자체 제작으로 전환한다. |
| P1 범퍼카 라이드 | 낮은 실내/차양 구조, 차량, 경계, 복구 전후 조명 | **Creator Store 후보를 선별해 다듬기 권장** | 차량과 반복 구성요소가 있어 검증된 베이스를 다듬을 수 있다. 차량 외형·색·트랙 경계와 차양을 바꾸고 기존 로고/스크립트를 제거한다. 모바일에서 차량과 탑승 공간이 겹쳐 보이지 않는지 확인한다. |
| P1 스낵 판매대 | 작은 키오스크, 차양, 진열창, 메뉴판, 폐허/복구 상태 | **자체 제작 권장** | 작은 화면에 명확히 읽히는 단순한 건축 형태가 적합하고 공원 브랜딩을 담을 수 있다. 둥근 모서리와 목재·크림·코랄 포인트를 시설 공통 규칙에 맞춘다. |
| P1 대기열·안전 소품 | 낮은 줄 서기 난간, 입구 표식, 운영/정지 표지 | **재사용 모듈 자체 제작** | 여러 놀이기구에 반복 배치한다. 작은 모바일 화면에서도 경계가 읽히고 진행 동선을 막지 않는 크기로 설계한다. |
| P1 전구·가로등·벤치·쓰레기통 | 고장 난 전구, 따뜻한 점등 상태, 좌석과 편의 소품 | **Creator Store 후보를 선별해 다듬기 권장** | 비대표 소품은 제작 시간을 아끼되, 크기·재질·색을 맞추고 불필요한 부품과 텍스처를 정리한다. 전구 발광은 가까운 범위의 적은 광원으로 제한한다. |
| P1 손님 캐릭터 | Roblox 아바타 기반의 간단한 방문객 외형, 소수 색상 변형 | **기존 Roblox 아바타 표현을 활용하고 외형을 다듬기** | 사람 형태를 새로 모델링하기보다 읽기 쉬운 실루엣·밝은 복장 변형으로 손님 존재를 보여준다. 복잡한 액세서리와 커스텀 리그는 최소화한다. |
| P1 수리/복구 피드백 | 수리 표식, 짧은 반짝임, 전구 점등, 선택적인 작은 색종이 효과 | **아이콘·간단한 효과는 자체 제작** | 복구의 기쁨을 빠르고 선명하게 전달한다. 짧고 절제된 효과로 시야와 모바일 성능을 지킨다. |
| P1 HUD 그래픽 | 티켓 아이콘, 단순한 둥근 패널, 수리 안내 상태 아이콘 | **자체 제작** | 작은 해상도와 게임 팔레트에 맞춘다. 숫자와 핵심 액션이 장식보다 우선이며 Roblox 기본 조작 UI를 가리지 않는다. |
| P2 공원 표지·장식 | 방향 표지, 운영 안내, 깃발/배너, 작은 화단 | **베이스가 있으면 선별·다듬기, 고유 글자·그래픽은 자체 제작** | 안내 정보를 간결하게 전달하고 세계관을 보강한다. 원본 브랜드 문구나 상표는 제거하고 한 공원에서 만든 듯한 공통 아이콘을 적용한다. |
| P2 이벤트 효과·오디오 | 짧은 정전 연출, 차단된 조명, 복구 알림음, 공원 배경음/놀이기구 소리 | **효과음은 직접 제작 또는 사용 조건이 명확한 에셋을 선별** | 짧은 정전 이벤트의 이해를 돕는다. 반복 재생 피로와 갑작스러운 큰 음량을 피하고, 기존 유명 놀이공원의 음악·효과음을 흉내 내거나 사용하지 않는다. |

**직접 모델링이 우선인 자산:** 회전목마, 입구/브랜딩, 스낵 판매대, 조경·수리 피드백 키트. 이 요소가 ParkPark의 개성을 결정한다. **선별 후 다듬을 자산:** 티컵, 범퍼카, 비대표 편의 소품과 손님 표현. 원본을 그대로 끼워 넣기보다 공원 팔레트·비율·재질에 맞게 다듬고, 필요하면 자체 제작으로 바꾼다.

## Creator Store 검색·선별 전략

### 검색어 출발점

Creator Store 검색은 영어 검색어를 함께 사용해 후보 폭을 넓힌다. 검색어는 모델의 라이선스·구성·품질을 보증하지 않는다.

| 대상 | 검색어 예시 |
| --- | --- |
| 회전목마 참고 후보 (완성품 복사 용도 아님) | `stylized low poly carousel`, `cartoon carousel ride` |
| 티컵 | `stylized teacup ride`, `low poly amusement teacups` |
| 범퍼카 | `stylized bumper cars ride`, `low poly bumper car arena` |
| 공원 소품 | `stylized park bench`, `cartoon vintage street lamp`, `low poly queue fence` |
| 조경 | `stylized weeds grass clump`, `cartoon flower planter` |
| 표지 참고 | `cartoon park sign`, `stylized kiosk` |

### 선별 순서

1. 이름뿐 아니라 미리보기, 제작자/업로드 출처, 설명, 라이선스와 사용 조건을 읽고 프로젝트 사용 권한이 분명한 후보만 남긴다. 출처와 URL/Asset ID, 확인 날짜, 수정 여부를 에셋 인벤토리에 기록한다.
2. 모델 내부의 스크립트, 플러그인 유도, 불필요한 실행 구성요소를 검토한다. 모델 에셋에 포함된 스크립트를 무비판적으로 사용하지 않는다.
3. 부품·메시·텍스처·머티리얼 수와 크기를 확인한다. 용도를 벗어난 고밀도 메시, 과한 조명·파티클·텍스처가 있는 후보는 제외하거나 경량화한다.
4. 로고·상표·유명 공원을 연상시키는 실루엣과 장식은 제외한다. 원본의 색·재질·크기·장식이 ParkPark와 맞지 않으면 수정 비용을 평가하고, 비용이 크면 자체 제작으로 전환한다.
5. 인게임 카메라 거리와 모바일 화면에서 실루엣, 충돌/상호작용 여유 공간, 복구 전후 가독성을 확인한 후 채택한다.

### 수정·성능 기준

- 팔레트와 재질을 통일하고 원본 로고/문구를 제거한다. 필요한 경우 차양, 좌석, 장식 실루엣을 변경해 공원 고유 외형을 만든다.
- 반복 소품은 재사용 가능한 단위로 정리하고, 장식 파츠는 플레이어 동선·카메라 시야·수리 대상에서 떨어뜨린다.
- 모바일을 기본으로 불필요한 부품, 투명 겹침, 복잡한 텍스처, 상시 파티클, 다수의 실시간 광원을 줄인다. 실제 기기에서 프레임과 가독성을 함께 확인한다.
- 발광 효과는 복구된 상태의 인상적인 소수 전구에 집중한다. 복구 전후를 조명만으로 구분하지 말고 색·형태·장식 상태도 함께 바꾼다.

## 제작 순서와 완료 기준

1. **회전목마:** 자체 콘셉트와 실루엣, 폐허/복구 상태를 먼저 결정한다. 입구 시점과 작은 모바일 캡처에서 대표 형상이 즉시 읽혀야 한다.
2. **입구와 첫 구역:** 표지판, 동선, 조경 키트로 회전목마를 향한 첫 화면을 완성한다. 폐허 상태에서도 통행 가능하고 수리 지점이 쉽게 발견되어야 한다.
3. **복구 피드백과 HUD:** 같은 순간에 티켓 보상, 복구 색, 전구 점등 및 짧은 효과를 알아볼 수 있게 한다.
4. **나머지 MVP 시설:** 티컵, 범퍼카, 스낵 판매대를 같은 재질·모서리·간판 규칙으로 맞춘다.
5. **최종 확인:** 모바일의 여러 화면비와 저사양 설정에서 입구부터 목표까지의 가독성, 복구 전후 차이, 에셋 성능을 검수한다.

## 코드 분리 리팩터링 계획 — 계획만

현재 [`src/server/Bootstrap.server.luau`](../src/server/Bootstrap.server.luau)는 `ParkParkWorld` 폴더 생성, 입구·회전목마 graybox 생성, 수리 프롬프트 검증, 플레이어별 일회성 보상, 회전목마 전체 시각 변경, `leaderstats.Tickets` 초기화를 한 파일에서 수행한다. 다음은 이 동작을 모듈로 나눌 **향후 계획**이며 아직 코드는 변경하지 않는다.

| 모듈 | 책임 분리 계획 |
| --- | --- |
| `ParkBuilder` | 월드/시설 참조를 찾고, 필수 구조가 없을 때만 개발용 graybox를 세우는 초기화 책임. 이후에는 이름으로 박아 만든 형상 대신 승인된 아트 에셋을 연결하도록 전환한다. |
| `RideService` | 회전목마 수리 프롬프트 연결, 플레이어/거리/생존 검증, 공유 시설의 복구 상태와 플레이어별 보상 청구 여부 관리. 복구 시 시각 상태 전환을 호출한다. |
| `EconomyService` | `leaderstats.Tickets` 생성과 시작 잔액 초기화, 검증된 보상 지급을 한곳에서 관리한다. 티켓 수 변경의 권한은 서버에 둔다. |
| `HUDController` | 클라이언트 티켓 표시와 값 변경 구독을 관리하고, 작은 화면 여백과 티켓/수리 피드백 시각 규칙을 적용한다. |

먼저 각 모듈의 입력·출력 계약을 정하고 Bootstrap은 서비스 초기화와 연결만 담당하게 한다. 공유 회전목마 상태와 플레이어별 보상 횟수는 분리해, 향후 저장/멀티플레이 정책을 바꿔도 시설 아트와 경제 처리가 서로 뒤섞이지 않게 한다.
